## Routing and high BAR

The subclass uses CacheLensX86Board's predeclared INTx route, PCI device 2,
function 0, pin 1, line 17, host `pc.pci_host`. Only PIO attaches to iobus.
`get_dma_ports()` retains IDE then NIC as separate Ruby sequencers/requestors.
Every requestor targets the HNFs; each core has private L1/L2.

`RubyPort::MemResponsePort::recvTimingReq()` tests `isPhysMemAddress()` and
sends non-RAM requests through `memRequestPort`. `System::isMemAddr()` uses
`main_mem_ranges`; `RubySequencer.connectIOPorts()` connects directly to iobus.
Consequently a BAR starting at **17GiB** goes to the NIC's dynamically advertised
PIO responder without a classic bridge or additional sequencer range. Keep the
base 1MiB PCI aperture at `0xC0000000` in `mem_ranges`, not `main_mem_ranges`.
Structural checks assert RAM/BAR-window disjointness and actual port peers.
They do **not** prove a live high-BAR transaction completed: the future native
peer test must program/read a BAR there, inspect readback/completion and ensure
no CHI payload request is generated by the MMIO access.

## Checks

From this native worktree:

```sh
python3 -m py_compile configs/simbricks/i40e_accuracy.py verification/accuracy/*.py
python3 verification/accuracy/test_config_contract.py
bash -n verification/accuracy/run_native.sh
# AFTER parent confirms native build completion, in its runtime environment:
bash verification/accuracy/run_native.sh /absolute/path/to/new-evidence
```

The host check executes the isolated memory override with a range stub: exact
16GiB sum, holes, nonoverlap, and rejection of other sizes/non-Ruby. It is not a
native simulation. Configuration mode constructs the real eight-core board and
hierarchy but never instantiates or connects sockets. It writes
`accuracy-configuration.json` with `accuracy_ready=false`.

`chi_payload_directed.py` uses the existing MESIDDIODirectedTester with **two
required data-only CPU ports**, not a guest/ISA execution test. Its HNF geometry
and policy match the config; its 64MiB SimpleMemory backing is test-only.
Primary tagged DMA uses requestor 1; an idle, separately connected race port
uses requestor 0. It checks full-line data, cold miss/hit update, NIC→CPU→NIC
coherence, exact RX bank routing, allocation only in ways 0/1, and separate
RX payload/header/descriptor/TX/RDMA counters. `stash_unclassified` is merely
an existing scenario name: stashing remains OFF. These are **policy proofs,
not i40e/SimBricks integration** and not a capacity-stress/back-invalidation proof.

`--mode boot-mmio` requires explicit `--kernel`, `--disk-image`, `--readfile`,
`--pcap`, `--pci-socket`, `--ethernet-socket`. Inputs are SHA256 recorded; the
base disk setup wraps the readonly raw disk in a COW image. Reuse unchanged:

- `gem5/work/sources/simbricks-prototype/guest/kernel-build/vmlinux`
- `gem5/work/sources/simbricks-prototype/guest/rootfs-i40e-rxonly-v2.ext2`
- `gem5/work/sources/simbricks-prototype/guest/rss/run.sh`
- `gem5/work/verification/simbricks-i40e-prototype/rss-4096-400k.pcap`

Compare hashes with the existing `rxonly-sync-cached-v6/manifest.json` under
that verification tree before launch. The inherited guest validates 8 cores,
16GiB, kernel 6.18.2, unsafe-no-IOMMU VFIO, four RSS workers and packet content.
Retaining those four queues is a functional regression only, not a single-queue
accuracy experiment. Check guest exit/result/queue/cleanup markers, not just
m5 exit code. The old `check_rxonly.py` contains useful acceptance requirements
but its classic `system` topology and ROI-file schema do NOT apply unchanged.

Both native peers must require semantic DMA v1; config sets `semantic_dma=True`.
PCI and SimBricksEthernet both synchronize at 500ns, with 500ns adapter latency;
the serializing EtherLink is 10Gbps/200us. The deferred PCAP source is silent
until the first workbegin(0,0) after guest readiness. Workend/exit ordering is
checked; diagnostics do not reset stats or call this an accuracy ROI.

## Remaining integration and measurement gates

1. Fail closed on absent/malformed semantic negotiation; demonstrate real
   i40e RX descriptor reads and payload writes reach the dedicated NIC requestor
   with classification preserved through line splitting and partial writes.
   Capture queue, packet, operation, requestor, PCI/physical address, byte range,
   and completion identity. Reconcile packet bytes and line counts separately.
   Admin/descriptor/header traffic must not contaminate RX payload counters.
2. Adapter source currently exposes `semanticDma.descReadOps`, `descReadBytes`,
   `payloadWriteOps`, `payloadWriteBytes` per queue; `untaggedReadBytes`,
   `untaggedWriteBytes`, and `traceDropped`. Optional `semantic_dma_trace`
   records bounded CSV; any dropped trace rows invalidate a complete-trace proof.
   These operation counts are NOT queue occupancy means.
3. Supply time-weighted `rxReplenishQueue::mean`, `rxQueue::mean`, and
   `rxInFlightQueue::mean` equivalents with documented ownership, units and
   transitions for the real i40e queues; add conservation and finite-drain proof.
   No guessed conversion from trace counts or reuse of unrelated E1000 stats.
4. Freeze warmup and a packet-complete, drained ROI before outcomes; record
   warmup, reset, source EOF, final DMA/guest completion, and final dump.
   Include carry-in/out, retries/drops, RSS affinity and compiled payload-touch
   behavior. Boot workitems alone do not satisfy this gate.
5. Future comparison follows `gem5/experiments/rxonly-pilot/compare.py`:
   `dpdk_rxonly_pipeline(replenish_mean, rx_mean + inflight_mean, packet_lines=23,
   touched_lines=verified_value)`. Compare x86
   `prediction.access_hit_rates['RX_REPLENISH']` against
   `sum(HNF.cache.rxPayloadHits) / sum(HNF.cache.rxPayloadRequests)` with positive
   denominator and requests=hits+misses per HNF. Threshold stays **5 percentage
   points**, fixed before results. This is NIC-write payload acceptance hit rate,
   NOT CPU/general demand hits, generic DMA hits, or average bank hit rates.
   Resolve actual HNF stat paths from native configuration; do not hardcode old
   MESI or E1000 paths. No comparison/calibration implementation is added here.
